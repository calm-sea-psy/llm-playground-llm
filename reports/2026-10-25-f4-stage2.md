# F4 LLM 벤치 2단계 (결선) — 2026-10-25-f4-stage2

**선정: gemma4:12b · think off** (`models/gemma4-12b.yaml`). 결선 후보 gemma4:12b · qwen3.5:9b (둘 다 think off, 1단계 `reports/2026-10-24-f4-stage1.md` 에서 고름)를 1단계에 없던 롱테일 문항으로 다시 쟀다. 차이는 100문항당 3~4문항으로 작고 방향이 엇갈린다 — 답 있음은 gemma 가, 사실 없음 · 지연은 qwen 이 낫다.

세트 `f4-longtail-stage2-ba21dfc5` — longtail(답 있음) 300 · no_fact(사실 없음) 200. 검색 결과를 고정한 문항(상위 5 문맥)이라 end-to-end 정확도가 아니다. 프롬프트 `bench/prompts` (f4_rag@v1 · f4_question_rag@v1 · f4_norag@v1), temperature 0 · seed 0 · num_ctx 8192 · max_tokens 256. 채점은 자동 (판정기 없음). 기록 2,000건 (2 spec × (rag 500 + norag 500)), 실행 1,267초.

## 결선 세트

llm-playground-wiki `scripts/build_longtail_set.py stage2` 로 만들었다. 1단계 세트 `f4-longtail-cec763d5` 의 문항 230 과 그 주제(Wikidata QID) 230 을 빼고, 1단계와 같은 규칙(속성마다 돌아가며 · 한 주제에 문항 하나 · seed 0)으로 골랐다 — 1단계와 겹치는 문항 · 주제 0, 세트 안 주제 중복 0.

- 사실 없음을 먼저 골랐다. 남은 사실 없음 주제가 328 이고 그중 237 은 답 있음 문항도 있는 주제라, 답 있음이 먼저 고르면 한 주제 하나 규칙에 사실 없음 몫이 준다.
- 사실 없음은 속성 10종만 남아 출생지 39 · 출신 학교 38 · 사망지 35 쪽으로 쏠렸다 (1단계는 16종 고르게). 답 있음은 16종.
- 정답이 든 문맥 순위 1위 268/300 · 2위 26 · 3위 6. 주제 문서 도입부가 문맥에 있는 문항 longtail 294/300 · no_fact 195/200.

## 짝지은 비교 (gemma4:12b − qwen3.5:9b)

두 후보가 같은 문항을 돌았으므로 문항마다 짝지어 본다. 차이 · 구간은 evalkit `paired_bootstrap` (2000회 · seed 0, 95%), 0 · 1 지표는 `mcnemar_exact` 도 — 한쪽만 = gemma 만 해당 : qwen 만 해당 문항 수. 칸은 %, 차이는 %p.

- EM (띄어쓰기 무시) = EM 이 0 이어도 답과 정답이 공백만 다르면 맞음으로 친다. qwen 이 날짜를 띄어 쓰는 버릇(아래 형식) 때문에 EM 이 실제보다 크게 벌어져서 따로 둔다. F1 은 원래 공백을 빼고 문자로 세므로 영향이 없다.
- 문자열 null 뺌 = JSON `null` 대신 글자 `"null"` 을 낸 답을 위반 · 지어냄에서 뺀 값. 지금 채점은 이 답을 "답함"으로 세서 지어냄으로 분류한다 — 답을 못 낸 형식 실패로 따로 세야 맞다.

## 결정

gemma4:12b · think off. 차이가 작고 엇갈려, 답 있음 정답률(F1 +3.7)과 한국어 표기(날짜 띄어쓰기 · 글자 "null" 이 없음)를 사실 없음 위반 4%p · 지연 0.4초보다 앞에 뒀다.

- 받아들인 것: 답이 없어야 할 문항에서 답하는 비율이 두 세트 모두 gemma 가 높다 — 사실 없음 13.0 vs 9.0 (합산 300), 1단계 문서 없음 26.0 vs 18.0 (n 50). 위반은 거의 '문맥에서 짐작' 이다. F9 (위키 레포 답변 평가)의 grounded 지어냄 비율로 다시 본다.
- 1단계의 다른 지표 (1단계 리포트): KorQuAD F1 86.7 vs 86.0 · 반사실 문맥 따름 94.0 vs 82.0 · 간접 인젝션 성공 2.0 vs 0.0 · 직접 인젝션 유출 3.3 vs 0.0 (30문항 중 1 vs 0).
- 벤치 설정(temperature 0 · max_tokens 256 · JSON 짧은 답)은 제품 프로필(위키 `configs/answer.yaml` — temperature 0.1 · 줄글 · base@v4)과 다르다. 이 벤치에서는 모델 순위만 옮긴다.
- 결선 후보 재실행(안정성 확인)은 하지 않았다 — temperature 0 · seed 고정이다.
